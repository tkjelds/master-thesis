\section{Context}
AI usage in software engineering has become an integral part of writing software, with one survey claiming more than 90\% of developers use AI tools \cite{jetbrains2025developer}. Recent developments in agentic harnesses (Example: Copilot, Codex, Claude code and Cursor) have also been widely adopted with the same surveyed group, about 29\% use GitHub Copilot for their work.\newline 
The use of concurrency is motivated by the potential performance gains enabled by modern multicore-CPUs. However, concurrency introduces significant complexity. Managing multiple threads that share resources can create a seemingly stochastic execution environment in which repeated runs of the same program produce different results. This, combined with the stochastic nature of LLMs.

\section{State of the research}
Many current benchmarks and analyses of LLM generated code focus primarily on sequential programs, leaving a blind spot for concurrent programs. The Concur benchmark \cite{huang2026concur} was developed in part to address this gap. It contains a base set of more than 40 concurrency problems drawn from concurrency textbooks, and uses formal model checking to validate concurrency properties of the generated programs. \newline
The study found that LLM generated programs vary considerably in their concurrency correctness. However model checking can be very time-consuming, which may restrict use in actual development environments. The study also only examined chat-models, and not agentic harnesses, which continue to rise in popularity among developers. \newline
Other studies have investigated scalable concurrency analysis \cite{jåtten2025scalablethreadsafetyanalysisjava}, in which the tool \textbf{CodeQL} was used across some of the most popular open-source repos. The findings of that study resulted in multiple pull-requests for concurrency fixes. 
  

\section{Proposed solution}
Given the importance of concurrency in modern software, along with the prevalence of LLM-generated code. It is important to investigate capabilities of modern LLMs with respect to concurrent programming. As mentioned, the previous study \cite{huang2026concur} used model-checking approaches, but at the time of writing no benchmark has used static analysis tools to investigate the capabilities of modern LLMs and agentic harnesses with respect to concurrent programs. The thesis seeks to address that gap, while also investigating the capabilities of agentic harnesses with respect to concurrent programs. \newline{}
The project intends to develop a benchmarking and evaluation tool for investigating LLM performance on concurrency problems using static analysis tools, such as \textbf{CodeQL}. The benchmark will evaluate both conventional LLM models and agentic coding harnesses, in an attempt to better reflect modern LLM usage in software development. A potential extension would be to extend the benchmark into a development tool that can provide feedback to AI tools by iteratively evaluating their implementation and guiding them towards safer concurrent code.	

\section{Research questions}
Formally the thesis seeks to answer the following research questions.
\begin{itemize}
	\item{\textbf{RQ.1} How well does the static analysis tool perform with respect to finding concurrency bugs in LLM generated code}
	\item{\textbf{RQ.2} How well does the static analysis tool perform with respect to runtime performance}
	\item{\textbf{RQ.3} Is there a performance gap between traditional LLMs versus agentic harnesses with respect to concurrency bugs found by static analysis tools.}
	
\end{itemize}
